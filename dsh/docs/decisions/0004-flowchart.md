# 0004 以流程图为中心组织课程

状态：已采纳。日期：2026-11-01。修订 [0003](0003-tutorialkit.md)：0003 删除了 Explorer 的插件树和回放，这里在 TutorialKit 的预览面板里把它们重新做出来，并让课程围绕它展开。

## 背景

0003 之后，每一课的反馈只有终端里的文字。Explorer 的分层插件树（L0 根作用域到 L4 编排，节点是插件，连线是依赖、注册和数据流）虽然单独看教学价值有限，却是理解“一切皆插件”最直接的图。学习者需要的不是一张预先画好的图，而是看着自己写的代码一步步把它画出来。

## 决定

1. **流程图是每一课的预览。** 模板的 `start` 命令预加载 `harness/diagram/server.ts`，它起一个 HTTP 服务（端口 4300），TutorialKit 把它显示在预览面板里（`previews: [[4300, '流程图']]`）。页面通过 SSE 接收更新，`node --watch` 重启后自动重连。服务保持进程存活，并接住未捕获的错误，所以 `main.ts` 跑完或抛错后图仍然可看。
2. **图从运行时读出来，不预先画。** `harness/diagram/recorder.ts` 观察 Cordis 根：
   - 节点是具名 fiber，状态取自 fiber。层次先查内核插件表，其余按规则算：提供服务又依赖服务的在 L2，只提供服务的在 L1，只依赖 `llm` 的在 L2（模型适配器），其余在 L3。agent 作用域画在 L3。
   - 依赖线来自 `inject`，注册线来自 effect 标签（`tools.register()`、`systemPrompt.section()`、`ctx.on("…")` 等）。
   - 数据流来自 `internal/dispatch`：用户输入、`agent/pre-step`、`system-prompt/assemble`、`llm/stream`、`tools/*`、`session/event`，加上运行器记录的模型响应和课程检查点。接收方是按作用域过滤后的监听器；组装提示词和执行工具还指向往对应服务登记过内容的插件，模型响应从处理它的适配器发回。
   - 记录器只读 Cordis 4.0.5 和上游发布包的内部字段（`events._hooks`、`reflect._getImpl`、`llm.adapters`），不改变任何调用。
3. **课程从空的根开始画。** “内核架构”部分的第一章不再直接给出完整内核：`createHarness({ kernel: [] })` 从空根开始，依次挂出 L1 的五个基础服务、L2 的工具运行时、L4 的 agent loop 和模型适配器、L3 的第一个课程插件。之后每一课在图上指出自己的机制出现在哪里；“插件实战”部分最后一课把写过的插件挂到一起，画出完整的图。直接使用 `new Context()` 的课程用 `draw(root)` 把自己的根交给流程图。
4. **界面让给流程图。** 终端默认收起，预览面板右上角可以展开。TutorialKit 1.6 把编辑器和预览的比例写死为 50/50，用 `pnpm patch` 改成 32/68（`patches/@tutorialkit__react@1.6.0.patch`）。图在窄屏下缩放，步骤列表是可收起的侧栏。
5. **面向新手。** 新增“从零开始”部分（`0-start`），用一个装好的 agent 讲清 agent、轮次、步骤和工具调用，再逐行读一遍课程代码，之后才进入从空根开始的内核架构部分。流程图默认是简明模式：连续的会话日志事件合成一步，每个节点和步骤附一句说明（`glossary.js`），节点可以点开看说明卡片；“完整步骤”切回逐条事件，选择保存在 localStorage。因为插入了第 0 部分，讲解里按名字（“内核架构”部分、“插件实战”部分）而不是编号引用各部分。
6. **验证。**
   - `lessons.spec.ts` 在运行每一课时通过 `LESSON_DIAGRAM_OUT` 拿到时间线，可以断言最后一帧的节点（标签、层、状态）和数据流步骤的顺序。
   - `diagram.spec.ts` 用最后一课的真实时间线检查布局（节点不重叠、不出界）、回放游标，以及简明模式的合并、回放停靠点和每个节点、步骤都有说明。
   - e2e 运行一课后等流程图的步骤列表出现模型回答，axe 连同预览里的流程图一起检查。

## 后果

- 记录器依赖上游未公开的内部字段。升级 Cordis 或 dsh 发布包时，`lessons.spec.ts` 的流程图断言会先失败，需要随之调整。
- 工具执行指向的是所有登记过工具的插件，不区分具体是哪一个工具；课程里只有计算器登记工具，所以没有歧义。
- TutorialKit 升级时要重新生成补丁。
- 终端仍然是完整输出的来源。只靠终端讲清楚的课程（例如 waterfall 的监听器直接挂在根上，图上只有根）在 frontmatter 里把终端设为默认展开。
